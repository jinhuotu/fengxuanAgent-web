# 边写边学协作流程（docs/learning-contract.md）

> 我要的不是写完的代码库，而是写的过程中学会。以下是硬流程，不是建议。
> 输出格式：先结论、一段一个意思、少列表、多短句、单句不超过 30 字。

## 一、动手前：先讲，再写

1. 用 3-5 句话讲清这一步在系统里的位置、为什么现在做它。
2. 列出新概念，最多 3 条，每条一句话解释 + 一个生活化比喻。
3. 说明要创建或修改哪些文件，每个一句话职责。
4. **停下来**，等我确认后再写。

## 二、写代码时

- 单次给出的代码不超过 60 行，超了先拆开讲一遍。
- 每个新概念第一次出现，加一行 `// 新手注意：……`。
- 关键判断、循环、拦截器位置写"在做什么"，不逐行翻译代码。
- 遵守 AGENTS.md 第三节（函数 ≤30 行、三行注释、完整变量名）。

## 三、写完必须停下来

- 用 3 句话说明这次数据怎么流动。
- 指出"你最该看懂第几行到第几行"，并说明为什么。
- 主动问一句"这里要不要我讲细一点"。
- **等我回"继续"再动下一步。**

## 四、我提问时

1. 先回答问题，不要边回答边继续写代码。
2. 概念用比喻讲，不堆官方文档原文。
3. 涉及 Vue/TS 特有写法（`<script setup>`、`ref`、`reactive`、组合式 API），补一句"在 Vue2/Java 里对应什么，没有对应就直说"。
4. 回答完问一句"继续刚才的进度吗"。

## 五、每次交付给五条

1. 文件清单：每个文件一句话作用。
2. 数据流转：5 行内白话讲清请求从哪进、经过哪几步、结果到哪去。
3. 改动定位：改接口地址 / 字段 / 提示文案，分别该动哪个文件第几处。
4. 完整命令：启动、构建、排查（从 `docs/commands.md` 取）。
5. 追加三行到 `docs/progress.md`：日期 / 决定了什么 / 为什么。

## 六、验收清单（逐条回报，每条给证据）

- [ ] `npm run build` 通过（含 `vue-tsc` 类型检查）
- [ ] `npm run dev` 能起，页面能打开（贴地址与状态码）
- [ ] 改动只涉及事先声明过的文件
- [ ] 没有新增依赖（或已获同意）
- [ ] 每个函数上方都有三行注释
- [ ] 没有留下 `console.log` 与注释掉的旧代码

## 七、阶段学习地图

- **阶段一 登录**：组合式 API、`ref`/`reactive`、表单校验、axios 拦截器、路由、token 存储、代理与跨域。
- **阶段二 权限**：路由守卫、按钮级权限、Pinia 里存用户信息、菜单按权限渲染。
- **阶段三 对话 + 知识库**：SSE 流式接收、消息列表渲染、上传、引用来源展示。
- **阶段四 多智能体**：任务状态可视化、多角色对话布局。

## 八、不许跳步的三件事

1. 不许一次做完一个阶段，拆成 5-8 个小功能逐个验收。
2. 不许引入我没听过、也没同意过的库。
3. 不许在我还没看懂上一段代码时继续往下写，我会直接说"停"。
